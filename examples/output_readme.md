# 杠精审查报告

## 判决

典型自嗨，建议重想。100 个 prompt 不叫产品，叫整理癖。

## 第一刀：最致命的问题

你的 README 第一屏没有告诉我“哪个 prompt 真的救过命”。它只告诉我你收集了很多东西。问题是互联网上最不缺的就是“很多东西”，缺的是可信筛选。

## 第二刀：你以为的需求 vs 真实需求

你以为用户缺 prompt。真实情况是用户缺一个能在具体任务里稳定出结果的 prompt。用户不是想逛 prompt 超市，他是想解决“我今晚要写完这份方案”或者“这个 bug 我卡了 2 小时”的问题。

## 第三刀：别人为什么不用你

别人可以直接问 ChatGPT，可以搜 GitHub，可以看小红书和博客。你没有评分依据、失败案例、适用边界、对比结果，就没有信任。社区投稿听起来热闹，但很可能把质量继续稀释。

## 第四刀：最可能死在哪里

1. prompt 数量越多，用户越不知道先用哪个。
2. 没有真实任务验证，README 看起来像复制粘贴合集。
3. 分类、搜索、收藏这些功能解决的是管理问题，不是效果问题。

## 第五刀：如果非要做，怎么砍

砍到 10 个 prompt，只服务一个高频场景，比如“程序员写 README 和 issue”。每个 prompt 必须有输入、输出、失败案例、适用边界和替代写法。第一版不要浏览器插件，不要社区投稿，不要收藏系统。

## 第六刀：下一步验证动作

1. 选 10 个真实 GitHub 项目，用你的 prompt 改 README，展示前后对比。
2. 发一个帖子，只放 3 个 prompt 和真实结果，问大家愿不愿意 star。
3. 找 5 个开发者让他们现场用，记录哪里看不懂、哪里没效果、哪里想复制。

## 最后一句人话

别再把互联网垃圾重新打包了，用户要的是验过毒的刀，不是刀具批发市场。
