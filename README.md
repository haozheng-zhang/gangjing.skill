# 杠精.skill

你的 AI 朋友负责鼓励你，杠精负责救你。

一个专门喷醒自嗨项目、伪需求、烂 PRD、技术炫技和创业幻觉的中文 Agent Skill。

不要再问 AI：“你觉得这个想法怎么样？”
大多数 AI 会说：“这个想法很有潜力。”

杠精会说：

> “这个想法不是没潜力，是你还没证明有人需要。”

## 这是什么

`gangjing-skill` 是一个可放进 Claude Code、Codex、Cursor 等 agent 环境的中文 Skill，也附带一个本地 CLI。

它不是普通 AI review 工具，也不是温柔建议助手。它的定位是：先找项目死因，再给你一个能落地的砍法。

适合审：

- “我想做一个……”开头的项目 idea
- README 虚胖症
- PRD 伪需求
- 技术架构自嗨
- 创业 pitch 幻觉
- 学术选题和实验设计薄弱点

不适合：

- 需要情绪支持的时候
- 你只是想要彩虹屁的时候
- 医疗、法律、金融决策本身
- 已经有清晰用户和数据，只需要普通执行建议的任务

## 安装

```bash
pip install -e .
```

## 启动对话系统

启动本地 Web 对话界面：

```bash
gangjing-web
```

打开：

```text
http://127.0.0.1:8765
```

进入前端后，在左侧点击或复制 DeepSeek API key 获取地址：

```text
https://platform.deepseek.com/api_keys
```

创建 API key 后，把它填到页面左侧的“临时 API Key”输入框里，就可以直接开始对话。这个 key 只在当前浏览器里使用，不会写进项目文件。

如果你更喜欢提前配置环境变量，也可以这样启动：

```powershell
$env:DEEPSEEK_API_KEY="your-deepseek-api-key"
gangjing-web
```

## Agent Skill 用法

把 `skills/gangjing/SKILL.md` 放到你的 agent skill 目录里。

当你要审一个方案时，对 agent 说：

```text
使用杠精.skill，按 startup 模式审查下面这个创业想法：
……
```

或者：

```text
用 github 模式喷一下这个 README，重点看第一屏有没有 star 欲望。
```


## 模式

| mode | 适合喷什么 |
| --- | --- |
| `default` | 项目 idea、README、PRD、普通方案 |
| `product` | 伪需求、用户场景、功能堆砌、MVP 过重 |
| `tech` | 过度工程、架构自嗨、技术栈炫技、重复造轮子 |
| `startup` | 商业模式、分发渠道、竞争格局、付费意愿 |
| `github` | README、项目定位、star 增长、开发者 adoption |
| `academic` | 论文选题、研究动机、贡献不足、实验设计 |
| `gentle` | 低毒版，但仍然直接 |

## 输出长什么样

```markdown
# 杠精审查报告

## 判决
典型自嗨，建议重想。

## 第一刀：最致命的问题
……

## 第二刀：你以为的需求 vs 真实需求
……

## 第三刀：别人为什么不用你
……

## 第四刀：最可能死在哪里
……

## 第五刀：如果非要做，怎么砍
……

## 第六刀：下一步验证动作
……

## 最后一句人话
……
```

## 示例

### 示例 1：通用 agent 插件系统

用户输入：

> 我想做一个通用 agent 插件系统，别人做 IDE 或工具时可以直接接入。

杠精输出节选：

> 判决：暂缓死刑，先砍一半。你在解决框架作者的问题，不是在解决用户的问题。  
> 第一刀：最致命的问题是你把“通用”当价值，但开发者真正买账的是“立刻省事”。MCP、IDE 插件系统、agent 框架已经占了心智，你没有给出迁移理由。  
> 最后一句人话：别再给没人用的东西设计生态了，先证明它配活着。

### 示例 2：AI Todo App

用户输入：

> 我要做一个 AI Todo App，支持自动拆任务、自动提醒、自动总结。

杠精输出节选：

> 判决：不是项目，是幻觉。Todo 领域死过太多聪明人，你还没说出为什么你能活。  
> 第一刀：用户不是缺任务拆解，是缺执行动机。你自动拆得越细，用户越像在看一份自己不会做的遗嘱。  
> MVP：砍成“专治拖延的 24 小时任务逼迫器”，只服务一个场景：今天必须交付一个东西。

### 示例 3：100 个 AI prompt

用户输入：

> 我想做一个开源项目，集合 100 个 AI prompt，让大家直接复制使用。

杠精输出节选：

> 判决：典型自嗨，建议重想。100 个 prompt 不叫产品，叫整理癖。  
> 第一刀：大家不是找不到 prompt，是不知道哪个真有用。你没有验证、评分、场景、对比，就只是把互联网垃圾重新打包。  
> MVP：别做 100 个，做 10 个真实任务验证过的 prompt，并附失败案例和适用边界。

完整示例见 `examples/` 和 `skills/gangjing/examples/`。

## 设计原则

- 喷方案，不喷人。
- 先找死因，再给砍法。
- 不写空话，不做商业互吹。
- 每个建议都要能落到 48 小时内的验证动作。
- 输出要有截图传播感，但不能为了毒舌牺牲判断。
